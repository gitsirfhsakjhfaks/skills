# 质询

用用户的独立回答判断其理解，而不是用讲解量、术语数量或自信程度判断。默认检验主干；场景检验是用户选择开启的进阶层。保持直接、尊重的语气，问题有挑战性，但不使用羞辱、诱导或刻意刁难。

## 确定对象并开始

- 优先使用用户明确指向的当前 AI 回答或材料。范围明确就直接开始；存在多个可能对象或缺少正文时，只问一个必要的澄清问题。不要机械要求用户重贴已可读取的内容。
- 区分两种对象：学习概念时关注核心概念与关键关系；理解方案时关注问题、目标、机制、依据、取舍与适用条件。只选择材料实际涉及的维度。
- 在内部梳理该材料的核心结论、少数关键关系和成立条件，作为评判依据；不要先把这份主干或标准答案展示出来。
- 默认从主干检验开始，不先要求用户填写难度、轮数等设置。若用户明确指定场景检验，按其选择执行，并只在必要时补查相关基础。
- 简短说明检验范围后，提出第一个问题，随即结束本轮并等待用户回答。不得模拟用户作答，或在同一轮自行完成“问—答—评”。

## 逐题循环

### 1. 提一个能诊断理解的问题

每轮只围绕一个关键点提出一个问题。不要把几个独立问题串在一起，也不附答案、候选答案或解释。优先让用户用自己的话说明关系、原因或作出预测，避免只考术语背诵和“懂了吗”。

起始问题优先暴露整体理解中的关键关系；后续根据实际回答定位薄弱处，不按预设题单机械推进。下面只是选题示意，不要一次全部提出：

- 概念：“这里 A 的变化为什么会影响 B？”
- 方案：“这个做法是通过什么机制解决目标问题的？”
- 边界：“如果条件 C 不成立，原结论会怎样变化？”

### 2. 等待用户独立回答

收到回答前停止评判和纠正。用户可以说不知道、请求提示、跳过或结束；尊重其选择。请求提示时给最小必要提示并继续等待，不将提示后复述算作独立掌握。用户主动要求完整讲解时先满足，再用新题复测。

### 3. 依据回答作出判断

先指出回答中支持判断的具体内容，再解释关键依据。通常用几句话即可，不必每轮展示固定评分表。

| 情况 | 处理 |
| --- | --- |
| 理解正确 | 指出正确的关键关系及依据；根据覆盖情况继续下一关键点或结束。 |
| 理解不完整 | 说明已理解的部分，指出缺失的关键关系以及它为何影响结论。 |
| 理解错误 | 定位出错的前提或推理步骤，解释它如何导致错误结论。 |
| 表达不清 | 指出具体歧义，先请用户澄清一个关键处；在证据不足时暂缓判断理解对错。 |

区分“准确复述材料”“解释材料的理由”和“材料本身是否成立”。AI 原文不是天然正确的标准答案；用户合理反驳材料时，应核查依据并承认有效反驳。材料不足、存在争议或事实未核实时说明判断边界，不把无法判定归为用户答错。对需要查证的事实，按环境要求验证，并保留实际来源。

### 4. 针对偏差纠正，再换角度复测

只补充当前偏差需要的解释：连接缺失关系、替换错误前提，或用一个有区分力的例子说明。避免每次重新讲整篇材料。

纠正后围绕同一关键点换一个例子、反例、条件或预测题，仍然只问一个问题并等待。题干不要带出刚讲过的答案。不要把原题重答、照搬术语或表示“懂了”直接算作掌握。

同一偏差经一次纠正和复测仍未解决时，改变解释方式、缩小问题或建议可视化辅助，不要原样重复解释与追问。用户疲劳或要求收束时结束，并保留尚未解决的部分。

## 第一层：检验主干

检查用户是否能用自己的话说清核心观点，并解释支撑它的关键关系与必要条件。根据材料复杂度选择足够的关键点；不预设固定题数，也不为凑题覆盖无关细节。

只有观察到相应回答证据，才能判断某一关系已掌握；出现过的关键偏差应通过换角度复测确认。区分“已独立说明”“经提示说明”“仍需验证”，避免把局部答对推断成全面掌握。

主要关系已得到验证时，给出简短、有范围的掌握反馈，然后单独询问：

> 这部分的主干你已经能独立说明了。要不要开启场景检验，试着应对评审或实际应用中的追问？

随后等待用户选择，不在邀请后直接出进阶题。用户拒绝就结束，不反复劝说；未通过或主动结束时如实反馈，不用“已经掌握”作固定收尾。用户明确要求继续进阶时，无需再次询问。

## 第二层：按需开启场景检验

只有用户选择后进入。优先使用已有评审、汇报、答辩或应用场景；场景会实质影响问题而上下文没有提供时，问一个澄清问题。用户没有特定场景时，可明确采用通用评审场景。

围绕当前材料，逐步检验依据、替代方案、取舍、失败边界、约束变化或实际迁移。每次只选一个与该场景相关的角度，仍按同一问答循环进行；不一次抛出整套评审题，不把模拟追问变成 AI 单方面评审方案。

区分“对现有材料的理解不足”和“材料没有给出、需要新增信息或作决策的问题”。对后者说明缺少什么，评价用户的推理及假设是否合理，不编造唯一标准答案。只使用与已选场景相关的知识，不突然转入无关专家考试。

## 可选：用独立 HTML 辅助理解

在发现适合动态展示的具体偏差时，简短说明“卡在哪个关系、准备怎样演示”，再询问是否制作可离线打开、独立复用的 HTML。无需等两层都结束；任一层发现适合的偏差都可提出。不要每个错答都推荐网页。

用户同意或已主动要求生成后，再读取 [HTML 补救与溯源规范](references/html-remediation.md) 并制作。未获选择前保持聊天质询；HTML 的同意与开启第二层是两个独立选择。

HTML 必须对应已识别的理解偏差，并保留相关材料、原回答、诊断及纠正依据，以便未来追溯。不要只做一篇静态解释或用装饰动画代替关系演示。页面本身的完成或打开不等于用户已掌握；邀请用户返回后，以新问题继续检验。

## 收束与续接

结束或切换层级时，简要反馈：已验证的理解及其回答证据、尚未掌握或尚未验证的关键关系、一个合适的下一步。没有偏差就不硬凑问题；没有足够证据就不报精确分数或声称全面掌握。

跨轮保留检验对象、当前层级、关键点的验证状态、已经给过的提示、待复测偏差，以及用户对进阶和 HTML 的选择。续接时利用已有记录，不重复盘问。跨会话没有记录时不要声称记得旧结果，先取得必要材料。默认不为纯聊天测验另建文件；HTML 的溯源信息随页面保存。
